# AGENTS.md

Этот файл описывает проект для любого AI-агента (Claude Code, Cursor, Aider,
Copilot Workspace и т.д.), который будет с ним работать. Это единственный
источник правды по конвенциям проекта — если другой файл (например CLAUDE.md)
что-то повторяет, он должен ссылаться сюда, а не расходиться в деталях.

## Что это за проект

Персональное портфолио DevOps-инженера. Статический сайт (без сборки,
без фреймворков, без npm-зависимостей во время выполнения). Цель — минимальная
стоимость размещения и обслуживания при сохранении профессионального вида
и демонстрации реальных DevOps-навыков через сам процесс разработки
(CI/CD, IaC, контейнеризация — см. раздел «Мета-демонстрация» ниже).

## Текущий этап и порядок работы

Основным выбран зелёный дизайн в стиле раннего Steam / CS 1.6. Репозиторий
публичный, GitHub Pages использует GitHub Actions. Разрешена автоматическая
публикация после успешного CI для каждого push в `main`. Личный контент пока
черновой: placeholders сохраняются, а сайт закрыт от индексации через HTML
meta и `robots.txt` до отдельного решения пользователя.

- Прямые указания пользователя определяют задачу и исключения из конвенций.
  Общие правила для всех агентов хранятся здесь; `CLAUDE.md` ссылается на них.
- В начале работы проверь `git status`. Сохраняй чужие незакоммиченные
  изменения, редактируй точечно и не переписывай файлы ради мелких правок.
- В рамках задачи выполняй чтение, локальные правки (включая CI и IaC),
  проверки, локальный предпросмотр и создание рабочих веток без отдельного
  согласования каждого шага. Новые ветки по умолчанию называй `codex/...`.
- Автоматический деплой после push в `main` уже разрешён. Сам `git push`,
  изменения DNS и применение Terraform требуют явного указания пользователя.
  Удаление веток и переписывание истории также требуют явного разрешения.
  Уже полученное разрешение в рамках задачи повторно не запрашивай;
  подготовь и проверь изменения до запроса недостающего разрешения.
- Не добавляй зависимости и не подключай внешние сервисы без согласования.
  Запуск уже предусмотренных инструментов проверки не считается добавлением
  зависимости проекта. Секреты не записывай в исходники даже при подготовке IaC.
- Создавай новые файлы, когда они нужны для задачи; сохраняй структуру
  проекта и не добавляй артефакты «на будущее» без необходимости.

## Жёсткие ограничения (не нарушать без явного запроса пользователя)

1. **Никаких сборщиков и фреймворков.** Пользователь осознанно выбрал чистые
   HTML/CSS/JS. Не добавляй React, Vue, Webpack, Vite, Tailwind CLI и т.п.,
   даже если это «стандартная практика» — только если пользователь явно
   попросит об этом в чате.
2. **Никаких платных сервисов «по умолчанию».** Не подключай аналитику,
   формы обратной связи, CMS, базы данных или хостинг с фиксированной
   абонентской платой, не спросив пользователя. Стоимость — ключевое
   требование проекта.
3. **Не выдумывай личные данные.** Реальное имя, место работы, даты,
   проекты, сертификаты, ссылки на соцсети — только от пользователя.
   Если данных нет, оставляй маркер `TODO:` и placeholder в квадратных
   скобках (например `[Название компании]`), не придумывай правдоподобные
   детали.
4. **`infra/` и `docker/` — опциональны.** Это демонстрационные IaC/контейнер-
   артефакты (см. ниже), они не обязательны для публикации сайта через
   GitHub Pages. Не удаляй их без запроса, но и не считай обязательными
   к развёртыванию.
5. Не коммить секреты (`.tfvars`, токены DigitalOcean, API-ключи).
   `.gitignore` уже настроен — не убирай из него эти правила.

## Как запустить локально

Сборка не нужна — это обычные файлы. Любой из вариантов:

```bash
# Python (обычно уже установлен)
python3 -m http.server 8080 --directory docs

# Node (npx при необходимости загрузит инструмент)
npx serve docs
```

Открыть http://localhost:8080.

## Проверки качества и готовность изменений

Актуальные команды и параметры CI находятся в `.github/workflows/ci.yml`.
Локальная проверка HTML той же командой:

```bash
npx --yes html-validate "docs/**/*.html"
```

Ссылки в CI проверяет `lycheeverse/lychee-action`, секреты —
`gitleaks/gitleaks-action`. Для локального запуска нужны соответствующие
CLI; используй параметры из CI. `npx lychee` не является командой этого проекта.

- После правок HTML проверь валидность, локальные ссылки и якоря.
- После правок интерфейса проверь узкий и широкий экран, отсутствие
  горизонтального скролла, навигацию с клавиатуры и видимый фокус.
  Для анимаций проверь режим `prefers-reduced-motion`.
- После правок JS проверь затронутое поведение, отсутствие новых ошибок
  в консоли и доступность основного контента и навигации с отключённым JS.
- Для изменений документации достаточно проверить diff, согласованность
  инструкций и ссылок на файлы. Для CI, Docker и Terraform проверяй
  затронутую конфигурацию доступными локальными средствами без публикации
  или создания облачных ресурсов.
- Проверки соразмерны изменению. В итоговом сообщении укажи, что проверено,
  а что не запускалось и почему; не выдавай непроверенное за успешный результат.
- Пока контент не заполнен, placeholders допустимы и публичный сайт должен
  оставаться закрытым от индексации. Перед снятием `noindex` проверь весь
  `docs/` на `TODO:`, placeholders, демонстрационные контакты и URL;
  согласуй оставшиеся заглушки и не создавай ссылки на отсутствующее резюме.

## Деплой

Основной способ — GitHub Pages. Push в `main` запускает `.github/workflows/ci.yml`.
После успешного завершения workflow `CI Checks` событие `workflow_run` запускает
`.github/workflows/deploy.yml`, который извлекает проверенный commit SHA и
публикует содержимое `docs/`. При ошибке CI деплой пропускается. Не добавляй
прямой deploy по `push`, обходящий проверки.

До подключения домена поддерживай размещение сайта по пути `/portfolio/`.
При подключении домена сначала настрой его в GitHub Pages, затем обнови DNS,
`og:url`, `robots.txt` и добавь sitemap после готовности контента.

Альтернативный/демонстрационный способ — DigitalOcean App Platform через
Terraform в `infra/` (см. `infra/README.md`). Не включён по умолчанию —
активируется вручную пользователем.

## Стиль кода

- HTML: семантические теги (`<section>`, `<article>`, `<nav>`, `<time>`),
  атрибуты `alt` у всех изображений, один `<h1>` на страницу.
- CSS: палитра, типографика и повторяющиеся отступы — через CSS-переменные
  в `:root` в начале `steam.css` (design tokens). Используй существующие
  токены; добавляй новые для повторяющихся значений. Единичные геометрические
  значения (например, толщина границы или размер иконки) допустимы локально;
  отдельный токен для каждого числа не нужен.
- JS: без зависимостей, ES6+, прогрессивное улучшение (сайт должен быть
  читаем и с отключённым JS).
- Комментарии/сообщения агента — можно на русском, если пользователь
  общается на русском; код (имена переменных, классов) — на английском.

## Мета-демонстрация DevOps-навыков

Смысловая деталь проекта: сам репозиторий — часть портфолио. Наличие
рабочего CI/CD (`.github/workflows/`), IaC-модуля (`infra/`) и контейнера
для локальной разработки (`docker/`) — это то, что оценит технический
рекрутер, открыв репозиторий на GitHub. Держи эти артефакты рабочими
и опрятными, а не формальными заглушками.

## Коммиты

Формат: `type: краткое описание` (`feat`, `fix`, `content`, `chore`, `ci`,
`docs`). Например: `content: добавить раздел про AWS-сертификацию`.
