# CLAUDE.md

Эти инструкции — для Claude / Claude Code при работе в этом репозитории.

**Сначала прочитай `AGENTS.md`** — там основные конвенции проекта (структура,
ограничения, стиль кода, деплой). Этот файл не дублирует их, а дополняет
специфичными для Claude моментами.

## Приоритет источников

1. Прямая просьба пользователя в текущем чате — всегда главнее.
2. `AGENTS.md` — конвенции проекта по умолчанию.
3. Этот файл — как именно Claude Code должен действовать внутри этих конвенций.

## Что делать в начале сессии

- Проверь `git status` перед началом работы — не затирай незакоммиченные
  изменения пользователя.
- Если задача касается контента (текст «обо мне», опыт, проекты) —
  не выдумывай факты. Спроси пользователя или оставь `TODO:` с placeholder'ом
  в квадратных скобках. Это правило из `AGENTS.md`, здесь оно повторено, т.к.
  для этого проекта оно особенно важно нарушать не стоит.
- Если задача касается дизайна (`docs/assets/css/style.css`) — не ломай
  существующую систему design tokens (переменные в `:root`). Меняй значения
  переменных, а не разбрасывай новые hex-коды по файлу.

## Локальные команды, которые можно выполнять без подтверждения

```bash
python3 -m http.server 8080 --directory docs   # локальный просмотр
npx html-validate "docs/**/*.html"             # проверка HTML
git status / git diff / git log                # чтение состояния репозитория
```

## Действия, требующие явного подтверждения пользователя

- Любой `git push`, создание/удаление веток, force-push.
- Изменения в `.github/workflows/*.yml` (это влияет на реальный деплой).
- Изменения в `infra/*.tf` с реальными значениями токенов/доменов.
- Добавление любой новой зависимости, сервиса или платного ресурса.

## Границы

- Не создавай файлы вне структуры, описанной в `AGENTS.md`, без необходимости.
- Не переписывай `docs/index.html` целиком ради мелкой правки — редактируй
  точечно (`str_replace`-подобный подход), чтобы не терять ручные правки
  пользователя между сессиями.
- Если пользователь просит что-то, что явно увеличит стоимость хостинга
  (например, «добавь backend», «подключи базу данных», «сделай CMS») —
  сначала уточни у пользователя, ведь низкая стоимость — заявленное
  требование проекта, а не просто пожелание.
