# Гайд по контенту

Заполните эти данные — своим текстом замените placeholder'ы
(`[в квадратных скобках]`) прямо в `docs/index.html`, ищите `TODO:` в коде.

## 1. Hero (главный экран)
- Имя (можно + короткая фраза о специализации: "DevOps / SRE инженер")
- Одна фраза о фокусе (например: "Строю CI/CD-пайплайны и инфраструктуру,
  которая не будит по ночам")
- 2 кнопки: "Проекты" (якорь на #projects), "Написать" (mailto: или ссылка)

## 2. About
3-5 предложений: чем занимаетесь сейчас, сколько лет в индустрии,
какие масштабы систем поддерживали (не нужно точных цифр компании, если
не хотите — можно "распределённая система на 200+ сервисов" без названия).

## 3. Skills — сгруппируйте по категориям, оставьте только то, что реально знаете
- **Cloud & Infra:** AWS / GCP / Azure / DigitalOcean / Hetzner
- **CI/CD:** GitHub Actions / GitLab CI / Jenkins / ArgoCD
- **IaC:** Terraform / Ansible / Pulumi / CloudFormation
- **Containers:** Docker / Kubernetes / Helm / Nomad
- **Observability:** Prometheus / Grafana / ELK / Loki / Datadog
- **Scripting:** Bash / Python / Go

## 4. Experience (пайплайн-таймлайн)
Для каждого места работы — по одной "стадии":
- Название компании (или "Компания в сфере X", если NDA)
- Должность, период (например `2022 — сейчас`)
- 2-3 буллета: не обязанности, а результат ("Сократил время деплоя с 40 до
  6 минут", "Перевёл 12 сервисов на Kubernetes без простоя")

## 5. Projects / кейсы
На каждый проект: Проблема → Что сделал → Результат (метрика, если есть).
Ссылка на GitHub-репозиторий и/или демо. 3-6 проектов достаточно —
качество важнее количества.

## 6. Certifications
Список бейджей: название, год, ссылка на верификацию (если у провайдера
есть публичная страница верификации — например Credly для AWS).

## 7. Contact
- Email (можно защитить от спам-ботов через obfuscation в `main.js`,
  уже сделано)
- GitHub, LinkedIn, Telegram — по желанию
- Ссылка на резюме (PDF) — положите файл в `docs/assets/resume.pdf`
  и обновите ссылку в HTML

## Тон текста
Коротко, по делу, без «эффективного менеджера» лексики
("синергия", "проактивный подход"). DevOps-аудитория ценит конкретику
и цифры больше, чем прилагательные.
